# Deviations from FreeBSD

FreeBSD's names and behavior are the compatibility contract (DRIVER-MODEL.md §4.3). This file lists
where AbyssBSD differs, and why. A difference not listed here is a bug.

## Driver names for hardware FreeBSD has no driver for

| Name | Device | Why |
|---|---|---|
| `sbsa_gwdt` | Arm SBSA generic watchdog (GTDT) | FreeBSD 15.1 has no driver for it. The name follows the earlier FreeBSD bring-up branch for the Orange Pi 6 Plus, where it was first written. |
| `sky1_clk` | CIX Sky1 "ACPI clock provider" (`CIXHA010`, `\_SB.CCLK`) | FreeBSD has no driver for it. Bound only so `_DEP`s on it are met; it serves nothing (its AML speaks SCMI for an agent that knows no clocks). It follows the `sky1_` names of the AbyssBSD Project's FreeBSD port for the board. |
| `sky1_scmi` | CIX Sky1 SCMI agent (`CIXHA006`, `\_SB.SCMI`) | Not in FreeBSD, whose SCMI framework is devicetree only; the name and the polled transport are the AbyssBSD Project's FreeBSD port's. It serves the clock lines the platform's `CLKT` tables give. |
| `cix_mbox` | CIX Sky1 mailboxes (`CIXHA001`) | Not in FreeBSD; the AbyssBSD Project's FreeBSD port's name. Only the doorbell channel (8) is served, as there. |
| `scmi_shmem` on ACPI | SCMI shared memory (`CIXHA004`, `CIXHA005`) | FreeBSD's `scmi_shmem` attaches to devicetree nodes only. Here it binds the Sky1's ACPI nodes and maps nothing: the memory is the mailbox's message registers, which `cix_mbox` serves. |
| `sky1_reset` | CIX Sky1 S5 and FCH reset controllers (`CIXHA020`, `CIXHA021`) | FreeBSD has no driver for them: its drivers use the reset state firmware leaves. The platform's `RSTL` lines make them suppliers of most SoC devices. |
| `sky1_pinctrl` | CIX Sky1 FCH and S5 pin controllers (`CIXHA016`, `CIXHA017`) | FreeBSD has no driver for them: its drivers use the pads firmware programmed. Consumers name their pin groups in `_CRS`, which makes the controllers their suppliers. |
| `sky1_syscon` | CIX Sky1 shared register windows (`CIXHA018`) | FreeBSD has no driver for them. Devices name them by `_DSD` reference (the UARTs' `sky1,fch_cru`), which makes them suppliers. |
| `gpio` (`cdns_gpio` crate) | Cadence GPIO r1p02 on the CIX Sky1 (`CIXH1002`, `CIXH1003`) | FreeBSD has no driver for it. The class is the one every FreeBSD GPIO controller driver takes (`pl061`, `dwgpio`), so the controllers are `gpio0`–`gpio6`. |
| `cdnc_i2c` on ACPI | Cadence I2C r1p14 on the CIX Sky1 (`CIXH200B`) | FreeBSD's `cdnc_i2c` drives the same IP, but attaches only to `simplebus` (FDT). The name is FreeBSD's. |
| `acpi_cppc` | CPU frequency through ACPI `_CPC` (one per `_PSD` domain, under its first `cpuN`) | FreeBSD 15.1 has no CPPC driver. The name, levels (100 MHz apart, `_CPC`'s lowest to highest frequency), and `delivered_mhz` are the AbyssBSD Project's FreeBSD port's, which the board's FreeBSD runs. |

## Device tree

| What | FreeBSD | AbyssBSD | Why |
|---|---|---|---|
| arm64 `virtio_pci` on QEMU `virt` | FreeBSD would assign the unassigned legacy I/O BAR | The modern interface | Same driver and description FreeBSD 16 picks for transitional devices; no I/O BARs are assigned on arm64. |
| ACPI devices whose `_STA` says absent | Added, disabled | Not added (except `PNP0C0F` and `PNP0B00`) | `devinfo -v` shows neither; the recorded trees match. |
| Resource managers (`hw.bus.rman`) | Every `rman` (I/O ports, memory, IRQs, and each bus's own) with its resources and their owners | The node answers as `sysctl_rman` does, but lists no resource manager, so `devinfo -r` and `-u` show no resources and `libdevinfo` users (`devmatch`, `devctl`) see none | Drivers' resources are grants of the bus manager, not ranges carved from `rman`s; listing them as FreeBSD's managers comes with P9's `devinfo` comparison. |
| Devices on an I2C bus (`I2cSerialBusV2`) | `acpi_iicbus` deletes `acpi0`'s unattached child and adds its own under `iicbusN` | The same tree, but `acpi0` has already matched the device: one with no driver was reported unmatched (devctl `?`) under `acpi0` before `iicbus` takes it and reports it again; it keeps every resource its `_CRS` gives, where FreeBSD's `iicbus` child gets the first interrupt only. Once the bus has detached (`devctl detach` of its controller), an attach again finds no `acpi0` node to take, and the bus has only `iic` (FreeBSD adds the devices anew from the namespace) | The node moves with its firmware dependencies and lines, which `acpi0`'s one dependency walk builds (DRIVER-MODEL.md §9.3). On FreeBSD, whether `acpi0` probes such a device before its controller attaches depends on namespace order. |
| `iicbus` bus clock | `cdnc_i2c` runs at the bus's `dev.iicbus.N.frequency` (the slowest device's `ConnectionSpeed`, or 100 kHz), set again on each `iicbus_reset` | `dev.iicbus.N.frequency` is the same number, but `cdnc_i2c` runs at its `_DSD` `clock-frequency` (at most 400 kHz), and writing the sysctl changes nothing until a controller takes it | The controller is set up before its bus exists; taking the bus's rate on `I2CRSTCARD` comes with a provider operation to change it. |
| GPIO controllers' children | `gpioN` has `gpiobusN` (and `gpiocN`), and `gpio_aeiN` is a child of `gpiobusN` | `gpio_aeiN` is a child of `gpioN`; no `gpiobus` or `gpioc` | Consumers reach pins through the dependency graph, not `gpiobus`. `gpiobus` and `gpioc` (`/dev/gpiocN`) come with userland GPIO access. |
| Processors (`cpuN`) | `cx_supported`, `cx_lowest`, `cx_usage` and the other idle-state nodes | None of them | Idle states (`_LPI`, `_CST`) come later (ROADMAP P11). |
| cpufreq(4) | Absolute and relative drivers (`p4tcc`, `est` with throttling) combine into levels | Absolute drivers only, one per `cpufreqN`: the levels are its settings | The only frequency driver is `acpi_cppc`. Writing `dev.cpu.N.freq` sets every `cpufreq` device to its nearest level, as stock FreeBSD does (the board's FreeBSD port sets only the written CPU's domain). |
| Passive cooling (`acpi_tz`) | Only the first zone with `_PSV`, `_TC1`, `_TC2`, `_TSP` cools, through `cpufreq0` | Each zone cools the cpufreq device of the first processor its `_PSL` names, the first zone of each device; a zone naming none slows nothing | The AbyssBSD Project's FreeBSD port's change: `acpi_cppc` sets one domain, so cooling through `cpufreq0` would slow CPUs 0-1 for any hot zone and leave the other domains uncooled. `_SCP` (cooling policy) is not set: there are no power profiles yet. |
| DMA of an ACPI device without `_CCA` on arm64 | Non-coherent: busdma tags are, unless a driver that reads `_CCA` says otherwise, and `bus_dmamem_alloc` memory is uncacheable | Coherent: `acpi0` imposes coherency only where a `_CCA` (the device's or an ancestor's) says so | Every arm64 machine so far gives `_CCA` where it matters (QEMU `virt`: 1; the Sky1: 0 for its USB hosts, 1 for PCIe). A non-coherent device's shared memory stays cacheable, with its cache lines cleaned or invalidated around each access (as FreeBSD's USB stack also does), because the direct map cannot yet be split to map it uncached. |
| `hw.iommu.dma` (arm64) | 0: DMA is not translated unless `loader.conf` says so (the board's FreeBSD sets 1) | 1 when an SMMU attaches | Translation is what keeps the Sky1's PCIe DMA correct (IOMMU.md §1.1), and a board setting would be a driver bug ("nothing special"). [ADR-0022](adr/0022-smmuv3-in-p9.md), IOMMU.md §13 decision 2 |
| `hw.smmu.bypass_named` (arm64) | Not in upstream FreeBSD; the board's FreeBSD port compiles 1 in, and the board runs 0 | 0: the streams of named components without a driver abort | As the board's working FreeBSD runs. IOMMU.md §4.9, §13 decision 2 |
| `smmuN` while IOMMU.md's stages land | It translates (`dev.smmu.N.dma: 1`) and says `smmu1: 10 streams bypassed (reserved memory)`; its announce line lists `iomem … irq …` | Attached, its registers read and none written, the SMMU left as firmware left it, `dev.smmu.N.dma: 0`. The announce line lacks the resource list, as every `acpi0` child's does | IOMMU.md §8: stage 2 enables the SMMU (RMR bypass), stage 3 translates. Resource lists come with the resource managers (above) |
| An SMMUv3 without a feature the driver needs | Attach fails (`Some features are required but not supported by hardware.`) | It attaches with translation off, printing the same lines | What it would translate runs untranslated either way; the unit stays in the tree to be seen (IOMMU.md §4.7) |
| `devctl detach smmuN` | Detaches it | `EBUSY` | The devices it translates depend on it (a settle edge, IOMMU.md §4.3) |
| `hw.iommu` on amd64 | `GENERIC` has `options IOMMU`: `hw.iommu.dmar.*`, `hw.iommu.tbl_pagecnt`, `hw.iommu.batch_coalesce` (DMAR off by default) | No `hw.iommu` | x86 DMAR and AMD-Vi are deferred (IOMMU.md §9); `%iommu` reads `rid=` on both ISAs regardless |
| nvme(4) command timeouts | A callout per queue pair, armed on submission, stamps each command's deadline as it is sent and looks every half second (`nvme_qpair_timeout`) | One watchdog thread per controller, asleep while nothing is outstanding, looks at every queue every half second and stamps a command the first time it sees it: a command times out up to half a second later than on FreeBSD | The submission path reads no clock and takes no extra lock; the timeout is 30 s, so the slack is immaterial. The behavior on a timeout is FreeBSD's with `hw.nvme.enable_aborts=0` (its default): poll the queue (`System interrupt issues?` once if that found completions), then reset; a `CSTS` of all ones or with `CFS` resets at once |
| nvme(4) recovery | The reset runs in a taskqueue while the timeout callout keeps polling (`Waiting for reset to complete`); the admin queue's commands time out too, and abort commands may be enabled (`hw.nvme.enable_aborts`); a changed queue count after a reset panics | The reset runs in the watchdog thread itself, so nothing waits on it; admin commands stay polled, bounded by `admin_timeout_period` (and a controller reading all ones fails them at once), without the admin queue's counters or `dev.nvme.N.adminq`; `hw.nvme.enable_aborts` is not offered; a changed queue count fails the controller. `dev.nvme.N` has `num_io_queues`, `timeout_period`, `admin_timeout_period`, and the `num_*` counters (summed, and per `ioq.M` with `num_entries`, `num_trackers`, `recovery`, read-only), but not `format_timeout_period`, `int_coal_*`, `reset_stats`, `cap_lo`/`cap_hi`, `fail_on_reset`, `sq_head`/`sq_tail`/`cq_head`, or `dump_debug`. | The driver issues no asynchronous admin commands (no AERs, no aborts, no format) for a timeout to cover. Queue positions are under the queue's lock, which a sysctl read may not take |

## Drivers

| What | FreeBSD | AbyssBSD | Why |
|---|---|---|---|
| `rge` transmit watchdog | `sc_watchdog = 5` whenever frames are queued, and whenever `rge_txeof` runs with a frame still on the controller, completed or not; when the tick counts it to 0 it prints `rgeN: [ERR] TX timeout (watchdog)` and calls `rge_init_locked`, which returns at once because the interface is still `IFF_DRV_RUNNING`: nothing is reset | Armed when a frame is queued on an idle ring, rearmed only when a completion is reaped with frames still out, so neither new frames nor interrupts hold it off; at 0 the same message, `oerrors` + 1, and the chip is reinitialized (stopped, rings emptied, MAC and PHY initialized, started) | A stalled transmitter must be noticed and recovered; on the Orange Pi the network died with nothing printed |
| `rge` tick | `rge_tick` follows the link and fetches the MAC statistics | Also reaps sent frames (a lost completion interrupt does not trip the watchdog), takes received frames that waited a whole tick with no interrupt (`[ERR] RX stall: frames waiting with no interrupt (N so far)`), and checks the controller still answers. No MAC statistics (there is no `dev.rge.N.mac_stats` yet) | A lost interrupt otherwise stops reception for good, silently |
| `rge` system error interrupt | Counted (`intr_system_err_cnt`) and `rge_init_locked` called, which does nothing while running | `[ERR] system error, reinitializing`, and the chip is reinitialized | As above |
| `rge` device gone from the bus | Not checked: an interrupt whose status reads all ones is taken for work | Registers reading all ones print `[ERR] device not responding (registers read all ones), stopped` once; the link goes down and the driver touches the device no more until detach | A PCIe link that drops must not spin the interrupt thread or hang resets |
| `rge` failed reinitialization | Not reported (`rge_init_locked` returns nothing) | `[ERR] reinitialization failed: ...`, reported the 1st, 2nd, 4th, ... time; retried after 2, 4, ..., 64 ticks | A chip that does not come back is visible, without flooding the console |
| `rge` sending while down | `ENETDOWN` while `sc_stopped` | The frame is dropped with `ENOBUFS` and counted in `oerrors`, while the chip is reinitialized | The link layer's transmit reports only `ENOBUFS` |

## System calls and process behavior

FreeBSD's behavior wins unless this table says otherwise ([COMPATIBILITY.md](COMPATIBILITY.md)
§4). Temporary entries end at the point named in the last column.

| Area | What differs | Why | Until |
|---|---|---|---|
| Unimplemented system calls | A call FreeBSD has but we do not implement yet returns `ENOSYS` without `SIGSYS`. Numbers that are not system calls at all get `SIGSYS`, as on FreeBSD | libc probes some calls (Capsicum) and copes with `ENOSYS`. A signal would kill programs that run fine on FreeBSD, for a call FreeBSD would have answered | Each call as it lands |
| Capsicum | Capability mode, descriptor rights, and the `ioctl` and `fcntl` limits follow FreeBSD, ktrace's `KTR_CAPFAIL` records included, but there is no `kern.trap_enotcap` | Nothing in base sets it | When a program needs it |
| Jails | No virtual network stacks (`vnet`) or addresses (`ip4.addr` and `ip6.addr` are unknown parameters to `jail_set` and empty to `jail_get`; `ip4` and `ip6` are accepted, and a jail's sockets use the host's loopback addresses as an `ip4=inherit` jail's do); jail descriptors poll and are passed, but take no `kevent` (`EVFILT_JAILDESC` is `EINVAL`); a dying jail goes at once, not when its last reference does; `devfs_ruleset` is recorded, but devfs has no rules | No networking beyond loopback until P7; devfs rules are not needed by base's `jail(8)` path | P7 (networking); when needed |
| Audit | No security event auditing: the `audit`, `auditon`, `getaudit`/`setaudit` (and `_addr`), and `auditctl` calls are `ENOSYS`, so `jail`'s `allow.setaudit` has nothing to allow | No audit daemon runs on a stock system | When needed |
| Interrupt affinity | `cpuset -x` (`CPU_WHICH_IRQ`, `CPU_WHICH_ITHREAD`) binds the interrupt's threads to the CPU, but the interrupt itself stays on the CPU it was connected on (CPU 0 for drivers); `CPU_WHICH_INTRHANDLER` is accepted and changes nothing. IRQ numbers are a pin's, or from 64 for MSI, and `vmstat -i` names sources `irqN:` on arm64 too (INTRNG names them by controller) | Moving a vector to another CPU is not needed for binding to CPU 0, which suite p7 does | When an interrupt must move |
| `procctl` | `PROC_SPROTECT` is checked but protects nothing (there is no pager to kill a process for memory) | No paging | With a pager |
| Resource limits | `RLIMIT_SBSIZE`, `RLIMIT_UMTXP`, `RLIMIT_PIPEBUF`, and `RLIMIT_SWAP` are kept but not enforced | Per-user accounting of socket buffers, shared umtx pages, pipe memory, and swap is not kept yet | When a program needs it |
| MAC | No MAC framework: `setcred` with `SETCREDF_MAC_LABEL` is `EOPNOTSUPP`, and the `__mac_*` calls are absent | No MAC policy is loaded on a stock system | When one is needed |
| Core dumps | Mappings made with `MAP_NOCORE` (or `madvise(MADV_NOCORE)`) are dumped like the rest, and `kern.compress_user_cores` cannot be set (so neither it nor `PT_COREDUMP`'s `PC_COMPRESS` compresses, as on FreeBSD with the default 0) | No per-mapping no-core flag yet; no gzip or zstd compressor in the kernel | When a program needs them |
| arm64 pointer authentication | Not enabled for user mode: the ID registers user mode reads hide it (`API`, `APA`, `GPA`, `GPI`, `APA3`) and `AT_HWCAP` has no `HWCAP_PACA`, as on FreeBSD with pointer authentication disabled; `PAC` instructions run as no-ops | The kernel sets no keys | When a program needs it |
| UFS2 journal | Journaled soft updates (`FS_SUJ`: `newfs -j`, `tunefs -j enable`) are not kept: a read-write mount writes with soft updates alone and clears the flag, so FreeBSD's `fsck_ffs` checks the file system in full instead of replaying a journal that would be stale. An unclean journaled file system mounts read-write only when forced, as on FreeBSD. No background fsck: without `vfs.ffs.adjrefcnt` and the other `vfs.ffs` requests on snapshots, `fsck_ffs -F` says the kernel lacks support (exit 6) and `rc` checks every file system in the foreground | No journal or snapshots yet | SU+J |
| `nmount` | `tmpfs` (options `mode`, `uid`, `gid`), `ufs` (`force`, `acls`, `nfsv4acls`), and `msdosfs` (`uid`, `gid`, `mask`, `dirmask`, `shortnames`), with FreeBSD's generic flag options (`ro`, `noexec`, `nosuid`, `nosymfollow`, `noatime`, `sync`, and the rest); other options are ignored, and other types fail with `ENODEV`, as an unknown one does on FreeBSD. `update` changes only the generic flags, and only for `ufs` (tmpfs and msdosfs answer `EOPNOTSUPP`); `reload` (what `fsck_ffs` and `growfs` ask of a read-only mount they changed, as type `ffs`) reads the superblock and the in-core inodes again, but refuses with `EINVAL` a superblock whose layout changed (grown, check-hashes or soft updates switched), which FreeBSD takes in; going read-only does not wait for files open for writing (FreeBSD: `EBUSY` unless forced), whose later writes fail with `EROFS`. `nfsv4acls` (or a superblock with `FS_NFS4ACLS`) is refused with `EOPNOTSUPP` (see Extended attributes and ACLs) | Each type arrives with its milestone; no count of writers per vnode yet | — |
| Extended attributes and ACLs | UFS2 keeps both namespaces' extended attributes in the inode's area as FreeBSD does, and POSIX.1e ACLs in them on an `acls` mount (or `tunefs -a`); tmpfs keeps attributes but, as on FreeBSD, no ACLs. NFSv4 ACLs are not kept at all: `ACL_TYPE_NFS4` is `EINVAL`, and a UFS file system asking for them is not mounted. Writing an attribute does not clear set-id bits for an unprivileged writer, and UFS's minfree reserve is open to system-namespace attributes and closed to user ones, as the file system sees no credential (FreeBSD's `ffs_extwrite` does) | NFSv4 ACLs need their own access rules (`vaccess_acl_nfs4`) and inheritance; ZFS is their main user | — |
| msdosfs | No `kiconv` (`-L`, `-D`, `-W`): names are ISO 8859-1 bytes, as FreeBSD's msdosfs without them. A file renamed while in use keeps its old `st_ino` until its vnode goes (FreeBSD's changes to the new entry's place at once); a file made where a renamed in-use file's number points gets another. The ESP is mounted on `/boot/efi` by the kernel at boot (FreeBSD: by `fstab`), from the root's disk, or else the first disk with one | No locale conversion tables; numbers follow vnodes here, entries there; no `init` or `fstab` yet | P6 (`init`, `fstab`) |
| `rmdir("a/b/..")` | Always `EINVAL`; FreeBSD answers `EINVAL` or `ENOTEMPTY`, apparently by which lookup path ran | `vfs_lookup`'s rule for `..` as the last component of a removal | Permanent |
| devfs | No `/dev/fd`, `/dev/stdin` and the like, no `cuau0` or `ttyu0.init`, no `pci` node. Rules match a device by kind (`D_TAPE`, `D_DISK`, `D_TTY`, `D_MEM`) only, not by its other `cdevsw` flags; a jail sees every node its ruleset shows, without FreeBSD's check of the node's creator (`devfs_prison_check`); a mount ignores options it does not know rather than refusing them (`vfs_filteropt`). Disks have no serial number for `DIOCGIDENT`. A partition's `gpt/` and `gptid/` names stay while it is open by another name (FreeBSD's `glabel` withdraws them then) | Not needed yet | When a program needs them |
| UNIX-domain sockets | A peek (`MSG_PEEK`) at a stream or seqpacket socket returns no control messages (FreeBSD's copies them); a socket's `fcntl(F_SETOWN)`, `SIGIO`, and `SO_ACCEPTFILTER` are not there; `connectat` takes a path only | Nothing in base needs them yet | When a program needs them |
| Internet sockets (loopback, MULTIUSER.md §8.4) | `AF_INET` and `AF_INET6` UDP and TCP reach local addresses only: there is no interface but `lo0`, so anything off it is `ENETUNREACH` (no default route), as on a FreeBSD with only `lo0` configured. No raw sockets (`SOCK_RAW` is `EPROTONOSUPPORT`, so no `ping`), SCTP, UDP-Lite, multicast (`IP_ADD_MEMBERSHIP` and `IPV6_JOIN_GROUP` are `EADDRNOTAVAIL`), `SO_REUSEPORT_LB` balancing, accept filters (`SO_ACCEPTFILTER` is `ENOENT` on a listener), `SIGIO`/`SIGURG` (`F_SETOWN` and `SIOCSPGRP` are not there), `sendfile`, or TCP's `SO_LINGER` wait on close (a time of 0 resets, as FreeBSD's; any other closes without waiting). TCP has FreeBSD's states and the errors a program sees (refused, reset, `EPIPE`, `TIME_WAIT` for `2 * net.inet.tcp.msl_local`, the listen queue's `3/2` limit), but no segments: buffers do not grow (`SB_AUTOSIZE`), `TCP_INFO` carries only the state, MSS, and window, urgent data is marked only when the whole send fits the peer's window, a `FIN_WAIT_2` whose peer never closes stays (FreeBSD drops it after `net.inet.tcp.finwait2_timeout`), and a connection to its own address and port is refused (FreeBSD makes a simultaneous open). `net.inet.*.pcblist` lists every PCB to every caller (`security.bsd.see_other_uids` is not applied); `kern.file` (which `sockstat` matches PCBs to processes by) does not exist yet | Loopback is what `rc`'s daemons (`syslogd -s`, `sendmail`'s local relay) need before P7 brings interfaces, routing, and the protocols on the wire | P7 |
| Interfaces and netlink | `lo0` is attached at boot already configured as FreeBSD's `rc.d/netif` leaves it (`127.0.0.1/8`, `::1/128`, `fe80::1%lo0/64`, up), so programs started before `rc` (and the in-kernel tests) find it; `rc`'s `ifconfig lo0 inet 127.0.0.1/8` changes the address in place. There are no other interfaces, no cloning (`ifconfig lo1 create` is `EINVAL`), no interface groups but `lo`, and no media. Netlink serves `NETLINK_ROUTE`'s links, addresses, routes, and (an empty) neighbor dump; `NETLINK_GENERIC` answers every request `EOPNOTSUPP` (no families); no group notifications are sent; routing sockets (`PF_ROUTE`) are not there (`route` and `netstat -r` use netlink and `net.routetable`) | What `ifconfig`, `route`, `netstat -i`/`-r`, and `getifaddrs(3)` read and `rc` writes | P7 |
| md(4) | `mdconfig` attaches malloc and swap disks (both kept in kernel memory, allocated as written); vnode, preload, and null disks fail with `EOPNOTSUPP`, and `-l` lists nothing. Detaching a disk that is open or mounted (it or a partition of it) is `EBUSY` unless forced. `-L` labels are not kept (`geom md list` shows none) | No swap; vnode-backed disks are not needed yet | When a program needs them |
| GEOM (`kern.geom.confxml`, `conftxt`, `confdot`, `kern.disks`) | The mesh has geoms of the DISK, MD, PART, LABEL, DEV, and VFS classes; GENERIC's other classes (`RAID`, `SWAP`, `Flashmap`, and on amd64 `FD`) are listed, empty. PART reads GPT only (no MBR or BSD label), and uses only the primary table (a damaged primary with a good backup is no table; FreeBSD uses the backup, `CORRUPT`). LABEL makes `gpt/` and `gptid/` names only: no `ufsid/`, `ufs/`, `msdosfs/`, `iso9660/`, `diskid/`, or `glabel label` names. Ids are synthetic handles, not kernel addresses. There is no `/dev/geom.ctl`: libgeom's `getxml` falls back to the whole `confxml`, as it does on an error, and the write-side verbs (`gpart add`/`delete`/`resize`/`set`/`unset`/`commit`, `glabel label`, ...) fail. Opens are counted as FreeBSD's DEV class counts them, but an `O_WRONLY` open counts as a reader too and `O_EXCL` takes no exclusive count; opens and mounts that conflict are not refused (FreeBSD's `g_access` answers `EPERM`). A partition opened or mounted for writing hides its LABEL geoms, but their `/dev` nodes stay (see devfs), and they come back in their first order (FreeBSD tastes them again, newest first). Drivers do not describe their disks yet: `descr`, `ident`, and `lunid` are empty, `rotationrate` is `unknown`, and `fwheads`, `fwsectors`, `stripesize`, and `stripeoffset` are 0; NVMe disks have no `nvd` aliases. `kern.geom` has none of FreeBSD's tunables (`debugflags`, `notaste`, `label.*.enable`, ...) | The views `gpart show`/`list`, `geom … list`, and `glabel status` read are what base needs (rc's `gptboot`, `growfs`, `bsdinstall`); the rest comes with a writer of tables (`gpart`, the installer) | P8 (installer), drivers as described |
| `rfork` | `RFSPAWN`, `RFPROC \| RFFDG`, `RFPROC \| RFFDG \| RFMEM \| RFPPWAIT` (what `posix_spawn`, `fork`, and `vfork` are), and `RFPROC` (a shared descriptor table) work; other flag sets (shared memory without waiting, changes to the caller) are `EINVAL`. A process sharing its descriptor table keeps sharing it across `execve`, where FreeBSD unshares it first (`fdunshare`) | Nothing in base uses them | When a program needs them |
| Nice values | `setpriority` and `getpriority` keep each process's nice value with FreeBSD's rules, but it does not change the threads' scheduling | The time-sharing scheduler has no nice input below its base yet | P6.12 |
| umtx | COMPAT_FREEBSD10's `UMTX_OP_LOCK` and `UMTX_OP_UNLOCK` from a 32-bit caller (`UMTX_OP__32BIT`, `UMTX_OP__I386`) return `EOPNOTSUPP`; on arm64 an unaligned lock word is `EFAULT` (as FreeBSD's arm64), on amd64 any word works. `RLIMIT_UMTXP` does not limit `UMTX_OP_SHM` pages | No 32-bit processes run; limits come with credentials | P6.7 (the limit); permanent (32-bit) |

| System V IPC | The limits are FreeBSD's defaults and fixed (`kern.ipc.*` read-only); `kern.ipc.shmsegs`, `sema`, and `msqids` (what `ipcs` reads) are absent; nothing is per jail (a jail's `sysvshm`, `sysvsem`, and `sysvmsg` are accepted and shared with the host) | Tunables and the `ipcs` views come with `kern.ipc`'s writable nodes | When a program needs them |
